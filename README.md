# 形式风格图谱 · Form & Style Atlas

个人形式风格知识库。目标不是收集好看的图，而是回答一个具体问题：**「我看到的那种感觉，叫什么，凭什么这么判断？」**

因此每则条目都包含四层可检验的信息：名称 → 主要视觉特征 → 识别依据（可指认的细节证据）→ 易混辨析。
凡是证据薄弱、命名来自网络社群而非学界、或存在争议的地方，都写在「批判性备注」里，不做遮掩。

```bash
# 启动本地站点（零依赖，只需 Node 18+）

# 浏览器打开
http://127.0.0.1:4173
```

换端口：`$env:PORT=8080; node server.mjs`（Windows PowerShell）或 `PORT=8080 node server.mjs`。

### 发布到 GitHub

本机**不需要装 git** —— 用仓库自带的发布脚本走 GitHub API 提交：

```powershell
# 1) 建一个 fine-grained PAT，权限只需 Contents: Read and write
# 2) 把令牌放进当前会话的环境变量（不要写进任何文件）
$env:GITHUB_TOKEN = "github_pat_xxx"

# 3) 先空跑看一眼会传哪些文件（可选）
$env:DRY = "1"; node tools/deploy-github.mjs; Remove-Item Env:DRY

# 4) 正式发布
node tools/deploy-github.mjs
```

默认发到 `xiz711/xizzz` 的默认分支；换仓库/分支用 `$env:REPO`、`$env:BRANCH`。
脚本把所有文件打成 blob、**一次性**组成一个 commit 再移动分支引用，不会留下一堆中间提交。
`_shots/`、`node_modules/`、`.git/` 一律不上传 —— 其中 `_shots/` 里的无头浏览器 profile
含 Edge 的凭据文件，**绝不可入库**（`.gitignore` 里也已排除）。

> **这个站点不能直接挂 GitHub Pages。** 首页、检索、总览这些静态部分可以，
> 但「扩充」页的保存、文件夹的新建/重命名/删除、条目增删都依赖 `server.mjs` 的 `/api/*`
> —— Pages 只有静态托管，没有后端。想在公网用完整功能，需要一个能跑 Node 的主机
> （Render / Railway / Fly.io / 自己的服务器都行），启动命令 `node server.mjs`，端口读 `PORT`。

## 站点功能

打开站点就是主体本身：**左边一个检索框，右边一只文件夹**。
没有开场动画、没有字标、没有顶栏、没有侧栏区块、没有页脚、也没有图片内容。

| 页面 | 用途 |
| --- | --- |
| **首页** | 左栏检索框；右栏文件夹堆叠。**滚轮直接滑动切换**（也可拖拽或按上下键）；**双击**文件夹进入条目；**单击标题**改名；右上角 × 删除；右下角新建 |
| **分类** | 五个类别分组，逐条列出全部条目 |
| **总览** | 内嵌完整筛选（关键词 / 类别 / 年代 / 标签 / 排序）+ 收藏，一次比较全部条目；**类别、标签、条目都可在这里增删** |
| **标签** | 从视觉线索反查：高频标签云 + 按首字索引的全部标签，可多选叠加 |
| **辨识** | 把两种易混风格并排对照「识别依据」，并自动给出共同标签与差异判据 |
| **扩充** | 新增/编辑条目、上传条目配图、**为文件夹上传封面**、导入导出 JSON、管理类别 |

首页在检索时，右栏换成命中条目的列表（名称、类别、年代、第一条识别依据），左栏始终只有检索框。
顶栏与页脚已移除，因此其余页面的入口在「扩充」页与各页内部的交叉链接里；
首页也支持 `#/?folder=2` 或 `#/?folder=heritage` 直接定位到某只文件夹。

### 文件夹与案例

每只文件夹对应 `data/taxonomy.json` 里的一个类别，三个字段决定它在首页的样子：

- `cover`：可选。上传后替换虚线方框区域，成为文件夹封面；不上传则保持空位（方框内不写任何文字）。
- `nameZh` / `nameEn` / `desc`：文件夹名与说明。

**在首页直接管理文件夹**（写回 `taxonomy.json`，刷新即生效）：

| 操作 | 怎么用 |
| --- | --- |
| **进入** | **双击**文件夹卡片，进入该类别的条目列表 |
| **重命名** | **单击**标题文字，就地改，回车保存、`Esc` 放弃 |
| **新建** | 卡片**外侧右下角的「新建文件夹」**（只是一行文字，没有按钮框；文字颜色与文件夹名称一致） |
| **删除** | 卡片**右上角的 ×**（悬停卡片时浮现）。若该类别下还有条目，会先确认，再把条目整体移到「未分类」 |

**单击进不去、必须双击**，是因为单击要留给改名——两者都绑在卡片上，只能这样分开。

「新建文件夹」在渲染时先写在 `section` 里，随后由 `bindDeck()` **搬进当前文件夹那张卡片内部**
（`curCard.appendChild(addBtn)`），再用负偏移挂到卡片**外侧**的右下角。挂在卡片上，
**横版竖版、切换文件夹之后都是同一个相对位置**——靠外部偏移量去对齐是做不到的。

文件夹名称下面不再显示英文行（`nameEn` 仍保留在数据里，只是首页不渲染）。

### XIXI 字标：可以点散的四个字母

检索框上方是 `XIXI` 四个字母，**淡灰色**（`--ink-3`，比正文浅，是安静的装饰而不是标题）、
无衬线字形（收笔更圆）、间距拉开；`padding-left` 与 `.search__field` 取同一个值，首字母正对放大镜。
**点其中任意一个，它就停在原地开始在整个页面里无重力地缓慢漂流**：速度很小（约 10–19 px/秒）且方向随机，
纵向比横向更慢，撞到视口边缘折返，同时极慢地翻转角度。**不会消失，会一直漂下去。**
键盘可达（`Enter` / 空格同样触发）。

**两个坑，都是几何量出来的：**

1. **字标不能参与布局。** 它若在文档流里，字母起飞变成 `fixed` 之后整列会上缩，检索框跟着往上跑。
   现在字标 `position: absolute`、参照物是 `.search`（容器的底边含 `padding-bottom`，
   用 `bottom: 100%` 会挂出一个算不清的偏移；容器上任何 `transform` 还会改变参照框并把字标带跑）。
   实测起飞前后：**检索框、文件夹、新建入口的矩形完全一致**。`?fly=1` 可复现这一步。
2. **起点必须是算出来的，不能量。** 一开始的写法是「改完样式再量一次、用差值补偿」。
   实测在改成 `position: fixed` 之后，`getBoundingClientRect()` 会稳定返回 `(0, 10)`，
   补偿量因此算成 −141，字母直接落到视口左上角 —— 这正是「从画面左上角开始飘」的原因。
   现在改成**解析式落点**：`left/top` 直接写成点击前的视口坐标，`transform` 只承担漂移增量
   （`translate3d(dx, dy, 0) rotate(r)`，`dx=dy=0` 即起点）。落点可以推导，就不需要任何二次测量。
   实测四个字母的落点与字标里的原始位置完全一致。
3. `.is-flying` 里必须写 `transition: none`：`.wordmark__l` 上的 `transition` 会与逐帧写入的
   `transform` 打架（CSS 去插值 → 看起来像瞬移）。hover 也不能再给 `transform` 加位移。

位置不持久化，**刷新页面即回到检索框上方**；只在**首页**出现；
`prefers-reduced-motion: reduce` 下不漂流，点了也不动。

### 总览里的增删

`#/index` 的筛选行每一项都可增删：

- **类别**：每个类别 chip 右上角有 ×，行尾有「＋」新建一个空类别。删除逻辑与首页的文件夹删除完全一致
  （走同一个函数，所以「条目移到未分类」的行为也一致）。
- **标签**：标签是从条目里自动汇总的，另外维护一份**可用标签词表**（`data/tags.json`）：
  - `custom` —— 手工新增、条目里可能还没人用的标签
  - `hidden` —— 从列表里移除掉的标签
  「可用标签」= 条目里用到的 ∪ `custom`，再减去 `hidden`。**删除只改词表，不动任何条目**，
  所以随时能再加回来；条目上原本的标签始终保留。
- **条目**：每张卡片右上角有 ×，删除会同时清理该条目上传的图片（`?purge=1`）。
- **年代 / 排序**：年代由条目的 `era` 字段自动派生，排序是固定的三种方式（策展 / 名称 / 最新），
  这两项按设计**不提供增删**。

上传封面的入口在「扩充 → 类别管理 → 上传封面」。图片落在 `public/assets/uploads/`，
路径写回 `taxonomy.json`。

### 动效

- **文件夹切换**：滚轮直接滑动，不做「点下一步」。按累计位移判定方向、不依赖 `deltaMode`，
  因此鼠标滚轮与触控板手感一致；到首个或末个文件夹时不拦截滚动，把控制权交还给页面。
- **果冻衔接**：切换时**旧卡缩小、新卡放大**，两头同时动，不是旧卡直接消失：
  旧卡 `scale × 0.76` 并淡到 0.26 透明度（620ms），新卡从 `scale 0.88 / opacity 0.32`
  长到 `scale 1 / opacity 1`（680ms），两者都用 `back.out(1.4)` 的回弹缓动。
  由 `playFolderIn()` 用 GSAP 播放，没有 GSAP 时退回 CSS 稳态，切换照样可用。
- **指针响应**：指针靠近时文件夹向指针方向轻微偏移，带阻尼。
- **条目卡片**（分类 / 总览 / 检索结果里）：图片随滚动连续视差并轻微推近，悬停时在两张母题之间交叉淡入。
  位移上限取元素高度的 2.8%，内层缩放不小于 1.075，因此任何滚动位置都不会露出容器边缘。
- **无障碍**：全部动效受 `prefers-reduced-motion` 控制；
  `/` 聚焦检索；`Esc` 清空检索；上下键切换文件夹。

### 色彩

**纯白底 + 灰阶点缀蓝红**。背景 `#ffffff`，文字由黑到灰分三级（`#111111` / `#4a4a4a` / `#8c8c8c`）。

- **文件夹**：统一的**灰白色**面 + 深色文字，与纯白底色拉开一点点层次即可。
- **蓝** `#1f4fd8` / **红** `#d6261f`：只作点缀——检索框聚焦的图标环、选中/未选中的指示点、`进入 →`、重命名时聚焦的下划线等少量强调。

> 条目详情页的主图仍是按该风格形式规则生成的**该风格自身底色**的母题（包豪斯的米白、孟菲斯的奶油等），
> 这是刻意的：风格母题要还原该风格真实的用色，而不是统一成页面配色。
> 如需跟着变，改 `motif.js` 里各风格调色板的 `bg`。

检索支持中文子串与多关键词「与」逻辑，匹配范围包括名称、别名、特征、识别依据、标签、人物、作品、易混辨析与批判性备注。

## 持续扩充的三种方式

**1. 在站点里直接加（推荐）**
打开「扩充」→ 填写表单 → 保存。内容立即写入 `data/styles.json` 并永久保留。
图片可点击上传、拖入或直接粘贴（`Ctrl+V`）到表单里；上传的图片存在 `public/assets/uploads/`。
条目和类别都能增删改；仍有条目在用的类别不允许删除，避免数据变成孤儿。

**2. 批量导入**
「扩充」页的「导入 JSON」可接受 `[{...}]` 或 `{"styles":[...]}` 两种格式，按 `id` 合并：已存在则更新，新 id 则追加。

**3. 直接改数据文件**
`data/styles.json` 就是全部内容，可直接编辑，也可纳入 Git 版本管理。改完刷新页面即可。

## 工具脚本

```bash
node tools/check-content.mjs      # 内容体检：缺字段、识别依据过少、标签同义重复
node tools/merge-styles.mjs <批次文件.json>   # 把批次条目合入 styles.json
node tools/build-seed.mjs         # 由 data/ 生成 public/seed.js（离线兜底）
node tools/retag.mjs              # 重排标签体系（见脚本内注释）
node tools/shot.mjs --url <url> --out <前缀> --probe   # 截图与版面探针（需先启动带调试端口的浏览器）
node tools/dom-report.mjs <dump.txt> [关键词…]        # 检查某页渲染出的主内容与结构
node tools/folder-report.mjs <dump.txt>               # 检查文件夹堆叠的三层结构
```

`check-content.mjs` 是这个库的质量闸门：它会把「识别依据不足 5 条」「标签只在一则条目里出现」这类
一眼看不出的内容问题列成清单。建议每次批量补充内容后跑一次。

### 排错用的小工具

页面带了两个自检入口，改动前端后可直接用：

- **`?probe=1`**：在页面左下角列出比视口更宽的元素，以及每个 canvas 的绘制缓冲 / 显示尺寸 / 父容器尺寸
  是否一致。用于定位横向溢出与图像拉伸。
- **渲染错误边界**：任何视图函数抛错时，页面不会静默变空白，而是显示错误信息与「重新加载」按钮。

### 关于第三方依赖

**GSAP 3.12.5 是本地内置的**（`public/vendor/gsap.min.js`），仍然保持「零构建、零运行时联网」：
`index.html` 用普通 `<script>` 在 `app.js` 之前加载它，因此 `window.gsap` 可直接使用。
它只用于一处——文件夹切换的果冻缓动（`back.out(1.4)`）；没有 GSAP 时那段动画直接跳过，
退回 CSS 稳态，切换功能不受影响。

这样做是因为运行时依赖 CDN 会带来两个问题：断网打不开，以及版本漂移。
如果将来要升级，替换 `public/vendor/gsap.min.js` 即可，不需要改任何代码
（`tools/vendor-gsap.mjs` 记录了当初取回该文件的方式，仅供参考）。

> 早先为开场动画还内置过 `ScrollTrigger.min.js`。开场已按要求移除，该文件与所有相关代码
> 一并删掉了，不再加载。

## 关于生成式图形母题

库里的每个条目都需要一张能立住版面的图，但直接拿网络图片既有版权风险，也常常对不上风格本身。
因此 `motif.js` 把每则条目的 `id` 映射到一组**该风格的形式规则**（十二种母题：网格、条带、轨道、
圆弧、手绘混排、霓虹地平线、黏土团块、玻璃层、堆叠、显性网格、水墨晕染、几何块面）与一套调色板，
再用 `canvas` 确定性地绘制出来——同一个 `id` 永远得到同一张图。

- 这些图**是示意，不是历史作品**，页面上也如此标注。
- 上传真实的授权图片后，母题自动被替换。
- 想改某则条目的观感，编辑 `motif.js` 里的 `STYLE_HINTS`（新增条目可自行指定 `kind` 与 `palette`）。

## 数据与 API

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| GET | `/api/bootstrap` | 一次取回 styles + taxonomy + meta + tags |
| GET/POST | `/api/styles` | 列出 / 新增条目 |
| GET/PUT/DELETE | `/api/styles/:id` | 读取 / 更新 / 删除条目（`?purge=1` 同时清理其上传图片） |
| GET/PUT | `/api/taxonomy` | 读取 / 覆盖类别定义 |
| GET/PUT | `/api/tags` | 读取 / 覆盖可用标签词表（`{ custom, hidden }`） |
| POST | `/api/upload` | 上传图片（base64 data URL，≤ 12MB） |
| POST | `/api/import` | 批量导入条目 |

服务只监听 `127.0.0.1`，不对外网开放。数据写入采用「先写临时文件再改名」的原子方式，避免中途中断损坏文件。

## 已知边界

- **图像**：目前全部为生成式母题，未收录历史作品实拍图；如需收录，请自行确认许可并逐条填写作者与来源。
- **移动端**：已针对窄屏调整（左栏改为堆叠、检索栏吸顶、栅格单列），但验证环境的最小可用视口为 504px，
  更窄的视口未做实机校验。
- **动效验证**：视差、指针位移、悬停换图、文件夹切换的果冻缓动均依赖真实交互输入，只能用浏览器实机感受；
  无头截图中不会体现。已确认 `prefers-reduced-motion` 下全部关闭。
- **删除不可撤销**：条目、类别、文件夹的删除都是直接写数据文件，没有回收站。
  建议定期用「扩充 → 导出 JSON」存档；`data/` 三个文件是全部内容，备份它们就够了。
- **标签删除的语义**：「可用标签」词表只影响筛选面板里列出哪些标签；
  条目上已填的标签不会被改动，被移除的标签随时可以再加回来。
- **条目覆盖**：28 则是可用的起点，不是完整风格史。工艺美术运动、新艺术运动、未来主义、国际风格建筑、
  极简主义之后的当代分支等，都可按上面的模板继续补。
